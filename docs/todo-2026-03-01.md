# TODO 2026-03-01

Need to add the `Container` abstraction so that i can run job inside a docker container.
The job stays pretty much the same, the only difference being that it will delegate
it's commands to be ran by the `Container` instead, which means hiding things a bit more.

## Overview

Job

- owns lifecycle(start -> exec loop -> stop)
- emits events
- merges streams -> logger
- decides pass/fail

Container

- doesn't own and care about logging
- start(): creates the docker container
- exec(): runs the job's command, returns streams(stdout, stderr)
- stop(): stop, removes the container

The container basically becomes a wrapper over how to spawn a child process, doing pretty much
what `Bun.spawn` does itself.
This simplifies the current job's lifecycle and responsabilities

## Executor strategy

Have the `Container` implement an `Executor` interface, so that i can easily switch
the executor backend(eg: remote docker, ssh, k8s, etc).

```ts
type ExecHandle {
  { stdout: ReadableStream, stderr: ReadableStream, exited: Promise<number> }
}

interface Executor {
  start(): Promise<void>;
  exec(cmd: string[]): Promise<ExecHandle>;
  stop(): Promise<void>;
}
```

## Error Handling

I suppose the best way to do it is to throw errors directly inside the container,
errors that would/should be caught by the Job.

It seems that the best way to do it is to capture the `stderr` of the command
and just throw with the output's message

  Fields: code?: string, message: string
  When: Bun.spawn() throws (ENOENT, EACCES)

  Type: StreamError
  Fields: stdout?: string, stderr?: string
  When: Pipe fails during execution
  ────────────────────────────────────────
  Type: Exited
  Fields: exitCode: number
  When: Process exits normally
  ────────────────────────────────────────
  Type: Killed
  Fields: signal: NodeJS.Signals
  When: Process killed by signal

  1. FailedToStart
  2. StreamError
  3. Killed
  4. Exited

  Type: job:started
  Fields: jobName
  When: Job process initialized, about to run commands
  ────────────────────────────────────────
  Type: command:started
  Fields: jobName, commandIndex
  When: About to run a command
  ────────────────────────────────────────
  Type: command:finished
  Fields: jobName, commandIndex, result
  When: Command completed (any result)
  ────────────────────────────────────────
  Type: job:finished
  Fields: jobName, success
  When: All commands done or fatal error
  Message Flow

  Happy path (all commands succeed)

  job:started        → { jobName }
  command:started    → { jobName, commandIndex: 0 }
  command:finished   → { jobName, commandIndex: 0, result: Exited }
  command:started    → { jobName, commandIndex: 1 }
  command:finished   → { jobName, commandIndex: 1, result: Exited }
  job:finished       → { jobName, success: true }

  FailedToStart

  job:started        → { jobName }
  command:started    → { jobName, commandIndex: 0 }
  command:finished   → { jobName, commandIndex: 0, result: FailedToStart }
  job:finished       → { jobName, success: false }

  Received: onExit only

  ────────────────────────────────────────

  Meaning: Job crashed before running commands
  ────────────────────────────────────────
  Received: job:started + command:started + onExit
  Meaning: Job crashed mid-command
  ────────────────────────────────────────
  Received: Full IPC flow + job:finished
  Meaning: Normal completion

  - ENOENT: Command not found in PATH

  Job Design Overview

  Architecture

  ┌─────────────┐         IPC          ┌─────────────┐
  │ Orchestrator │◄────────────────────│     Job     │
  │   (parent)   │    JobMessage[]     │   (child)   │
  └─────────────┘                      └─────────────┘
         │                                    │
         │ spawns multiple                    │ spawns commands
         │ Job processes                      │ sequentially
         ▼                                    ▼
     parallel jobs                    ┌───────────────┐
                                      │  Subprocess   │
                                      │ (Bun.spawn)   │
                                      └───────────────┘

  Types

  JobCommandResult (what can happen to a command)
  Type: FailedToStart
  Fields: code?: string, message: string
  When: Bun.spawn() throws (ENOENT, EACCES)
  ────────────────────────────────────────
  Type: StreamError
  Fields: stdout?: string, stderr?: string
  When: Pipe fails during execution
  ────────────────────────────────────────
  Type: Exited
  Fields: exitCode: number
  When: Process exits normally
  ────────────────────────────────────────
  Type: Killed
  Fields: signal: NodeJS.Signals
  When: Process killed by signal
  Priority order (most broken → least broken):
  1. FailedToStart
  2. StreamError
  3. Killed
  4. Exited

  JobMessage (IPC messages to orchestrator)
  Type: job:started
  Fields: jobName
  When: Job process initialized, about to run commands
  ────────────────────────────────────────
  Type: command:started
  Fields: jobName, commandIndex
  When: About to run a command
  ────────────────────────────────────────
  Type: command:finished
  Fields: jobName, commandIndex, result
  When: Command completed (any result)
  ────────────────────────────────────────
  Type: job:finished
  Fields: jobName, success
  When: All commands done or fatal error
  Message Flow

  Happy path (all commands succeed)

  job:started        → { jobName }
  command:started    → { jobName, commandIndex: 0 }
  command:finished   → { jobName, commandIndex: 0, result: Exited }
  command:started    → { jobName, commandIndex: 1 }
  command:finished   → { jobName, commandIndex: 1, result: Exited }
  job:finished       → { jobName, success: true }

  FailedToStart

  job:started        → { jobName }
  command:started    → { jobName, commandIndex: 0 }
  command:finished   → { jobName, commandIndex: 0, result: FailedToStart }
  job:finished       → { jobName, success: false }

  Orchestrator fallback (onExit without IPC)
  Received: onExit only
  Meaning: Job failed before initialization (constructor threw)
  ────────────────────────────────────────
  Received: job:started + onExit
  Meaning: Job crashed before running commands
  ────────────────────────────────────────
  Received: job:started + command:started + onExit
  Meaning: Job crashed mid-command
  ────────────────────────────────────────
  Received: Full IPC flow + job:finished
  Meaning: Normal completion
  Edge Cases

  Spawn errors

  - ENOENT: Command not found in PATH
  - EACCES: Permission denied (non-executable file)

  Exit vs Killed

  - subprocess.exitCode → process exited normally (0 = success, non-zero =
  error)
  - subprocess.signalCode → process killed by signal (SIGTERM, SIGKILL, etc.)
  - They're mutually exclusive

  Stream errors

  - With stdout: 'pipe', you must consume the stream
  - Both stdout and stderr can fail independently
  - Track per-stream: { stdout?: string, stderr?: string }

  IPC ordering

  - IPC messages should arrive before onExit, but not guaranteed
  - job:finished makes it explicit that Job completed its work
